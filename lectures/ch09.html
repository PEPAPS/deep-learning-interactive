Lecture 10 · Chapter 9

Convolutional Networks

A CNN is an ordinary neural network in which some layers use convolution instead of a full matrix multiplication. That one change — small kernels, shared across all positions — makes networks for images, audio and other grid-like data far smaller, faster and better at generalizing.

Where convolution fits in training

The training loop is unchanged. Convolution changes the forward pass (which function the layer computes), so the backward pass changes with it — and the smaller, structured model generalizes better from the same data.

Same as before

Loss (cross-entropy), back-propagation, SGD/Adam, regularization and batch norm all work as in L4–L9.

What changes

Each layer’s weight matrix is replaced by a small kernel that is slid over the input: few parameters, local connections.

9.1 · The convolution operation

Convolution: a sliding weighted average

To smooth noisy readings x(t), average recent ones with weights w(a) that depend on their age a. Doing that at every time t gives a new function s = x ∗ w, the convolution of the input with the kernel.

\[ s(t)=\int x(a)\,w(t-a)\,da \](9.1) \[ s(t)=(x*w)(t) \](9.2) \[ s(t)=(x*w)(t)=\sum_{a=-\infty}^{\infty}x(a)\,w(t-a) \](9.3) discrete time

In plain words

  • Example: a laser sensor gives the spaceship’s position x(t), but noisily. More recent readings are more relevant, so give them more weight.
  • For a true weighted average, w must be a valid probability density; and w(a) = 0 for negative ages, otherwise it “looks into the future”. These limits are specific to this example — in general, convolution is defined for any functions where the sum/integral exists.
  • In ML the input is a multidimensional array of data and the kernel a multidimensional array of learned parameters (both are called tensors). Outside the stored elements we treat them as 0, so the infinite sum is a finite one.

Input x
The first argument (here the sensor readings).
Kernel w
The second argument: the weights (learned in a CNN).
Feature map s
The output of a convolution.
Tensor
A multidimensional array (vector = 1-D, matrix = 2-D, …).
∗
The convolution operator.

Calculation, step by step

  1. Kernel w = (0.5, 0.3, 0.2) for ages 0, 1, 2. Readings x(8) = 4, x(9) = 6, x(10) = 5.
  2. \(s(10)=x(10)w(0)+x(9)w(1)+x(8)w(2)=5(0.5)+6(0.3)+4(0.2)\)
  3. \(=2.5+1.8+0.8=5.1\). The weights add up to 1, so this is a weighted average.

9.1 · Convolution over two axes

2-D convolution and cross-correlation

For an image I and a 2-D kernel K, each output pixel is the sum of an image patch multiplied element-wise by the kernel. True convolution flips the kernel; most libraries skip the flip (cross-correlation) but still call it convolution.

\[ S(i,j)=(I*K)(i,j)=\sum_m\sum_n I(m,n)\,K(i-m,j-n) \](9.4) \[ S(i,j)=(K*I)(i,j)=\sum_m\sum_n I(i-m,j-n)\,K(m,n) \](9.5) commutative \[ S(i,j)=(K*I)(i,j)=\sum_m\sum_n I(i+m,j+n)\,K(m,n) \](9.6) cross-correlation

In plain words

  • Convolution is commutative (9.4 = 9.5) because of the flip — handy for proofs. 9.5 is easier to implement (fewer valid values of m and n).
  • Neural networks learn the kernel anyway, so whether it is flipped doesn’t matter: a learned flipped kernel is just another kernel. Libraries implement cross-correlation (9.6).
  • Each output pixel only looks at a small neighbourhood → it detects a local pattern (edges, spots, textures) wherever it appears.

Terms on this slide

I(i, j)
Image brightness at row i, column j.
K(m, n)
Kernel (filter) weight at offset (m, n).
Kernel flip
Rotating the kernel by 180° (reversing rows and columns).
Cross-correlation
Convolution without the flip: slide K as it is.
Commutative
Order doesn’t matter: I ∗ K = K ∗ I.

Calculation, step by step

  1. Patch \(\begin{bmatrix}0&2&2\\0&2&2\\0&2&2\end{bmatrix}\), vertical-edge kernel \(\begin{bmatrix}1&0&-1\\1&0&-1\\1&0&-1\end{bmatrix}\).
  2. Row by row: (0·1 + 2·0 + 2·(−1)) × 3 rows = (−2) × 3 = −6: a strong edge (dark → bright).
  3. A flat patch (all 2s) gives 2 + 0 − 2 = 0 per row → 0: no edge.

9.1 · Convolution as matrix multiplication

Convolution is a constrained, sparse matrix

Discrete convolution is a matrix multiplication — but by a matrix whose entries are tied together (each row = the row above shifted) and that is mostly zeros. So any neural-network algorithm built on matrix multiplication works for convolution too.

\[ \mathbf y=\mathbf M\mathbf x,\qquad \mathbf M=\begin{bmatrix}a&b&c&0&0\\0&a&b&c&0\\0&0&a&b&c\end{bmatrix}\ \ (\text{Toeplitz}) \]

In plain words

  • 1-D: each row of M equals the row above shifted by one element — a Toeplitz matrix.
  • 2-D: the matrix is a doubly block circulant matrix (blocks of Toeplitz-like rows inside a block pattern).
  • Two constraints: many entries must equal other entries (sharing), and most entries are zero (the kernel is much smaller than the image).
  • Algorithms that only need “multiply by the matrix” (and its transpose, for back-prop) work without changes.

Terms on this slide

Toeplitz matrix
Constant along every diagonal.
Doubly block circulant
The 2-D version: a block matrix whose blocks repeat in shifted order.
Sparse matrix
A matrix that is mostly zeros.

Calculation, step by step

  1. Kernel (a, b, c) = (1, 2, −1), x = (2, 1, 0, 3, 1).
  2. Row 1: 1·2 + 2·1 + (−1)·0 = 4. Row 2: 1·1 + 2·0 + (−1)·3 = −2. Row 3: 1·0 + 2·3 + (−1)·1 = 5.
  3. Matrix 3×5 = 15 entries, 9 non-zero, only 3 distinct numbers.

9.2 · Motivation 1: sparse interactions

Sparse interactions: each output looks at a few inputs

Make the kernel smaller than the input: each output connects to only k inputs. Fewer parameters, less memory, fewer operations, better statistical efficiency — and depth still lets deep units see a large part of the input.

\[ \text{dense: } m\times n\ \text{parameters},\ O(m\times n)\ \text{runtime} \] \[ \text{sparse: } k\times n\ \text{parameters},\ O(k\times n)\ \text{runtime} \] \[ \text{receptive field after } L \text{ layers (stride 1): } 1+L(k-1) \]

In plain words

  • Traditional layers: every output interacts with every input. An image may have millions of pixels, but edges can be detected by kernels of tens or hundreds of pixels.
  • With m inputs and n outputs, limiting each output to k connections: k×n instead of m×n. Good performance is possible with k several orders of magnitude smaller than m.
  • Units in deeper layers indirectly interact with a larger portion of the input, so complex interactions are built from simple local pieces.

Terms on this slide

Sparse connectivity
Also “sparse weights”: each unit is connected to only a few units of the layer below.
Receptive field
The set of input units that can affect a given unit.
Statistical efficiency
Doing well from fewer training examples.
m, n, k
Number of inputs, outputs, connections per output.

Calculation, step by step

  1. m = n = 10 000, k = 9: dense 10⁸ weights; sparse 9×10⁴ = 90 000 → about 1 100× fewer.
  2. Receptive field with k = 3: layer 1 sees 3 inputs, layer 2 sees 1 + 2·2 = 5, layer 3 sees 7.

9.2 · Motivation 2: parameter sharing

Parameter sharing: learn one detector, use it everywhere

In a dense layer every weight is used once. In a convolution every kernel weight is used at every position. Runtime stays O(k×n), but storage drops to just k parameters.

\[ S(i,j)=I(i,j)-I(i,j-1)\qquad(\text{kernel }(-1,\ 1)) \]

In plain words

  • Instead of a separate set of parameters for every location, we learn one set (except perhaps at the borders).
  • Because k is tiny compared with m and n (which are usually similar), k parameters are practically nothing next to m×n.
  • Book example (Figure 9.6): a 320×280 image, kernel of 2 weights, output 319×280. Convolution needs 319·280·3 = 267 960 floating-point operations; the same map as a dense matrix needs over 8 billion entries — convolution is ~4 billion times more efficient to store and ~60 000 times more efficient to compute.
  • During training, the gradient of a shared weight is the sum of its gradients at all positions.

Terms on this slide

Parameter sharing
Using the same parameter for more than one function in a model (“tied weights”).
Edge
A place where brightness changes sharply.
Flop
One floating-point operation (a multiply or an add).

Calculation, step by step

  1. Outputs: 319 × 280 = 89 320. Each needs 2 multiplies + 1 add = 3 flops → 267 960 flops.
  2. Dense: inputs 320 × 280 = 89 600; matrix 89 600 × 89 320 ≈ 8.0 × 10⁹ entries, ≈ 1.6 × 10¹⁰ flops.
  3. Ratio of compute: 1.6 × 10¹⁰ / 267 960 ≈ 60 000. Storage: 8 × 10⁹ / 2 = 4 × 10⁹.

9.2 · Motivation 3: equivariant representations

Equivariance: move the input, the output moves too

Because the same kernel is used everywhere, convolution is equivariant to translation: shifting the input and then convolving gives the same result as convolving and then shifting.

\[ f\text{ is equivariant to }g\iff f\big(g(x)\big)=g\big(f(x)\big) \] \[ I'=g(I),\quad I'(x,y)=I(x-1,y)\ \ \Rightarrow\ \ g(I)*K=g(I*K) \]

In plain words

  • Time series: convolution produces a timeline of when features appear; move an event later and the same representation appears later.
  • Images: a 2-D map of where features appear; move the object and its representation moves the same amount.
  • Useful when the same local function (e.g. an edge detector) is useful everywhere — edges appear all over the image.
  • Not always wanted: for face-centred crops, the top should look for eyebrows and the bottom for a chin (→ locally connected layers).
  • Convolution is not naturally equivariant to scale or rotation.
  • Bonus: convolution can process inputs of different sizes, which a fixed-shape matrix cannot.

Terms on this slide

Equivariant
The output changes in the same way as the input.
Invariant
The output does not change at all (pooling, next part).
Translation
Shifting without rotating or resizing.

Calculation, step by step

  1. x = (0, 0, 1, 2, 0, 0), kernel (1, −1): output \(x_{t}-x_{t+1}\) = (0, −1, −1, 2, 0).
  2. Shift x right by 1: (0, 0, 0, 1, 2, 0) → output (0, 0, −1, −1, 2): the same numbers, one step later.

9.3 · Pooling

A convolutional layer: convolution → detector → pooling

A typical layer has three stages: several convolutions in parallel give linear activations; a nonlinearity (usually ReLU) is the detector stage; then pooling summarizes nearby outputs.

\[ z_{i,j}=(I\star K)_{i,j}+b,\qquad h_{i,j}=\max(0,z_{i,j}) \] \[ p_{u,v}=\max_{(i,j)\in\text{window}(u,v)}h_{i,j} \]

In plain words

  1. Convolution stage: affine transform (kernel + bias) → linear activations.
  2. Detector stage: ReLU (or another nonlinearity) keeps only where the feature is present.
  3. Pooling stage: replaces each location by a summary statistic of its neighbourhood (max, average, L² norm, distance-weighted average).

Two terminologies: a “complex layer” with three stages, or three “simple layers” (conv layer, detector layer, pooling layer).

Terms on this slide

Linear activation
Output of the convolution + bias, before the nonlinearity.
Detector stage
The nonlinearity applied to each linear activation.
Pooling
Summarize a neighbourhood by one number.
Max pooling
Report the maximum in a rectangular neighbourhood.

Calculation, step by step

  1. Conv outputs in a 2×2 window: (−6, 2, 0, 4); bias b = −1 → (−7, 1, −1, 3).
  2. ReLU: (0, 1, 0, 3).
  3. Max pool: max(0, 1, 0, 3) = 3. Average pool would give 4/4 = 1.

9.3 · Pooling

Pooling: invariance to small shifts, and fewer units

Pooling makes the representation approximately invariant to small translations — useful when we care whether a feature is present more than exactly where. Pooling with a stride also downsamples, and pooling into a fixed number of regions handles inputs of varying size.

\[ \text{max: }\max_{j\in R}h_j\qquad\text{average: }\frac1{|R|}\sum_{j\in R}h_j\qquad L^2\text{: }\sqrt{\sum_{j\in R}h_j^2} \] \[ \#\text{pooled outputs}=\Big\lfloor\frac{n-\text{width}}{\text{stride}}\Big\rfloor+1 \]

In plain words

  • To decide whether an image contains a face, we need an eye on the left and one on the right — not their pixel-perfect location.
  • Shifting by one pixel changes every detector value, but only some max-pooled values (max is sensitive to the largest value, not its position).
  • Pooling regions spaced k pixels apart → about k× fewer inputs to the next layer: faster, and fewer parameters if the next layer is fully connected.
  • Variable-size images: vary the offset between pooling regions so the classifier always gets the same number of summary statistics (e.g. one per quadrant).
  • Pooling regions can also be chosen dynamically (e.g. clustering interesting features) or learned once and applied to all images.

Terms on this slide

Invariance to translation
Shifting the input slightly leaves most outputs unchanged.
Stride (of pooling)
Distance between neighbouring pooling windows.
Downsampling
Keeping fewer values than you started with.
Summary statistic
One number describing a group (max, mean, norm).

Calculation, step by step

  1. Detector values (0.1, 1.0, 0.2, 0.1), max pool width 3, stride 1 → (max(0.1,1,0.2), max(1,0.2,0.1)) = (1.0, 1.0).
  2. Shift right, new value 0.3 enters: (0.3, 0.1, 1.0, 0.2) → (1.0, 1.0): no pooled value changed although every input did.
  3. 14 values, width 3, stride 2: ⌊(14 − 3)/2⌋ + 1 = 6 outputs.

9.4 · Convolution and pooling as an infinitely strong prior

Convolution and pooling as an infinitely strong prior

A CNN is a fully connected net with an infinitely strong prior: weights must be zero outside a small local region, and identical (but shifted) between neighbouring units. When this belief is right it greatly improves generalization; when it is wrong it causes underfitting.

\[ p(\boldsymbol\theta)=0\quad\text{unless both hold:} \] \[ W_{i,j}=0\ \text{outside a small window},\qquad W_{i,j}=W_{i+1,\,j+1}\ \text{(tied)} \]

In plain words

  • Weak prior (high entropy, e.g. a wide Gaussian): the data can move parameters freely. Strong prior: low entropy, actively decides where parameters end up. Infinitely strong: some values have zero probability — forbidden no matter what the data say.
  • Convolution’s prior: the layer learns only local interactions and is equivariant to translation. Pooling’s prior: each unit is invariant to small translations.
  • Underfitting risk: if a task needs precise spatial information, pooling everything raises the training error. Some architectures pool only some channels.
  • If a task needs information from very distant locations, the convolution prior may be inappropriate.
  • Fair comparisons: compare convolutional models with other convolutional models; permutation-invariant models must learn the topology from data.

Terms on this slide

Prior
Belief about good parameter values before seeing data.
Infinitely strong prior
Gives zero probability to some parameter values: they are completely forbidden.
Underfitting
Training error stays high because the model cannot represent the solution.
Permutation invariant
A model that would work just as well if the pixels were shuffled (it ignores topology).

Calculation, step by step

  1. 16 inputs → 14 outputs: dense layer 16 × 14 = 224 free weights.
  2. The prior forces 224 − 14·3 = 182 weights to 0 and ties the remaining 42 into 3 values: 3 free parameters.
  3. Fewer free parameters → lower capacity → less overfitting, if the prior matches the task.

9.5 · Variants of the basic convolution function

Many kernels, many channels

One kernel detects one kind of feature. Real layers apply many kernels in parallel to a multi-channel input (e.g. red, green, blue) — so inputs and outputs are 3-D tensors and the kernel is a 4-D tensor.

\[ Z_{i,j,k}=\sum_{l,m,n}V_{l,\,j+m-1,\,k+n-1}\,K_{i,l,m,n} \](9.7)

In plain words

  • V: input with element \(V_{i,j,k}\) = channel i, row j, column k. Z: output, same format.
  • \(K_{i,l,m,n}\): connection strength between output channel i and input channel l, with an offset of m rows and n columns.
  • The sum runs over all input channels l and all valid offsets m, n. (The −1 is because maths indexes from 1; in Python/C it disappears.)
  • Software works in batch mode: 4-D tensors with a 4th axis for the examples in the minibatch.
  • With multiple channels the linear operations are not guaranteed to be commutative, even with kernel flipping.

Terms on this slide

Channel
One “layer” of a grid: e.g. the red values of an image, or one feature map.
Kernel stack
All filters of one output channel (one per input channel).
4-D kernel tensor
Output channel × input channel × rows × columns.

Calculation, step by step

  1. RGB input (3 channels), 64 output channels, 3×3 kernels.
  2. Weights: 64 × 3 × 3 × 3 = 1 728, plus 64 biases = 1 792 parameters.
  3. Each output value: 3 × 3 × 3 = 27 multiply-adds (summing over all input channels).

9.5 · Stride

Strided convolution: skip positions to save work

Move the kernel s positions at a time: fewer outputs and less computation, at the cost of extracting features less finely. It equals a full (stride-1) convolution followed by downsampling.

\[ Z_{i,j,k}=c(\mathbf K,\mathbf V,s)_{i,j,k}=\sum_{l,m,n}\Big[V_{l,\,(j-1)\times s+m,\,(k-1)\times s+n}\,K_{i,l,m,n}\Big] \](9.8) \[ \text{output width}=\Big\lfloor\frac{m+p_{\text{left}}+p_{\text{right}}-k}{s}\Big\rfloor+1 \]

In plain words

  • s is the stride; we can use a different stride for each direction.
  • Computing all outputs and then throwing most away is wasteful — strided convolution computes only the ones we keep.
  • Stride and pooling both shrink feature maps, so later layers are cheaper.

Terms on this slide

Stride s
Step size of the kernel between neighbouring outputs.
c(K, V, s)
Name of the strided convolution function.
⌊·⌋
Round down (floor).

Calculation, step by step

  1. m = 9, k = 3, s = 2, no padding: ⌊(9 − 3)/2⌋ + 1 = 4 outputs, at positions 0, 2, 4, 6.
  2. Stride 1 would give 7 outputs; keeping every 2nd (0, 2, 4, 6) gives the same 4 numbers.
  3. 2-D 224×224 image, k = 7, s = 2, padding 3: ⌊(224 + 6 − 7)/2⌋ + 1 = 112.

9.5 · Zero padding

Zero padding: valid, same and full convolution

Without padding, each layer shrinks the width by k − 1, so we must choose between small kernels and a quickly shrinking network. Implicit zero padding lets us choose the kernel width and the output size independently.

\[ \text{valid: } m-k+1\qquad\text{same: } m\qquad\text{full: } m+k-1 \]

In plain words

  • Valid: no padding; the kernel only visits positions where it fits entirely. All outputs use the same number of inputs (regular behaviour), but the size shrinks every layer — eventually to 1×1, which limits depth.
  • Same: just enough zeros to keep output size = input size. Unlimited depth, but border pixels influence fewer outputs → under-represented.
  • Full: enough zeros that every pixel is visited k times in each direction; output m + k − 1. Border outputs depend on fewer real pixels, making one kernel hard to fit at all positions.
  • The best amount (by test accuracy) usually lies between valid and same.

Terms on this slide

Zero padding
Adding zeros around the input so the kernel can be centred on the border.
Valid / same / full
MATLAB’s names for no / size-preserving / maximal padding.

Calculation, step by step

  1. m = 7, k = 3: valid 5, same 7 (1 zero each side), full 9 (2 zeros each side).
  2. 32-pixel input, k = 5, valid: 28, 24, 20, … → after 7 layers 4, the 8th layer gives width 0: at most 7 layers.
  3. Same padding with k = 5: 2 zeros each side; the corner pixel is used by only 3 of the 5 kernel positions per direction.

9.5 · Locally connected layers, tiled convolution

Between “fully connected” and “convolution”

Keep the local connections but drop the sharing → a locally connected (unshared) layer. Share partly, cycling through t kernels → tiled convolution. Or restrict which channels connect → fewer parameters without fewer units.

\[ Z_{i,j,k}=\sum_{l,m,n}\big[V_{l,\,j+m-1,\,k+n-1}\,w_{i,j,k,l,m,n}\big] \](9.9) locally connected \[ Z_{i,j,k}=\sum_{l,m,n}V_{l,\,j+m-1,\,k+n-1}\,K_{i,l,m,n,\,j\%t+1,\,k\%t+1} \](9.10) tiled

In plain words

  • Locally connected: a 6-D weight tensor W — output channel i, output row j, output column k, input channel l, row offset m, column offset n. Same connectivity graph as convolution, but every connection has its own weight.
  • Use it when each feature should depend on a small part of space, but there is no reason the same feature appears everywhere (look for a mouth only in the bottom half of a face).
  • Tiled: learn a set of t kernels and rotate through them as you move. Neighbours get different filters, but memory grows only by a factor t. t = output width ⇒ locally connected; t = 1 ⇒ convolution.
  • Channel groups: the first group of output channels connects only to the first group of input channels, and so on — fewer parameters, less memory and computation, same number of hidden units.

Terms on this slide

Unshared convolution
Another name for a locally connected layer.
%
Modulo: remainder after division (t % t = 0, (t + 1) % t = 1).
t
Number of kernels the tiled layer cycles through.

Calculation, step by step

  1. 8 inputs, 6 outputs, k = 3 (1 channel).
  2. Fully connected: 8 × 6 = 48. Locally connected: 6 × 3 = 18. Tiled (t = 2): 2 × 3 = 6. Convolution: 3.
  3. Output j uses kernel number j % t: j = 0, 1, 2, 3 → kernels 0, 1, 0, 1.

9.5 · Gradients and biases

Back-propagation through a convolution

Convolution is multiplication by a sparse matrix M, so back-propagation multiplies the incoming gradient by Mᵀ (a “transposed convolution”). The kernel gradient sums over every position where the kernel was used.

\[ G_{i,j,k}=\frac{\partial}{\partial Z_{i,j,k}}J(\mathbf V,\mathbf K) \] \[ g(\mathbf G,\mathbf V,s)_{i,j,k,l}=\frac{\partial J}{\partial K_{i,j,k,l}}=\sum_{m,n}G_{i,m,n}\,V_{j,\,(m-1)\times s+k,\,(n-1)\times s+l} \](9.11) \[ h(\mathbf K,\mathbf G,s)_{i,j,k}=\frac{\partial J}{\partial V_{i,j,k}}=\sum_{\substack{l,m\\(l-1)s+m=j}}\ \sum_{\substack{n,p\\(n-1)s+p=k}}\ \sum_q K_{q,i,m,p}\,G_{q,l,n} \](9.12–9.13)

In plain words

  • Training needs ∂J/∂K (to update the kernel) and, unless this is the first layer, ∂J/∂V (to pass the error further down).
  • For stride > 1 these are not ordinary convolutions — they need their own implementations (g and h above).
  • The transpose must be coordinated with the forward pass: its output size depends on padding and stride, and several input sizes can give the same output size, so the original size must be given explicitly.
  • Biases: locally connected layers — one per unit; tiled — shared with the same tiling as the kernels; convolution — usually one per output channel, shared over all positions. A separate bias per location (for fixed-size inputs) can correct for, e.g., border units that receive less input because of zero padding.

Terms on this slide

G
Gradient of the loss with respect to the layer’s output Z (arrives from above).
g(G, V, s)
Function giving the kernel gradient.
h(K, G, s)
Function giving the input gradient (transposed convolution).
Transposed convolution
Multiplication by Mᵀ; also used to upsample.

Calculation, step by step

  1. x = (1, 2, 0, 1), k = (1, −1), stride 1: z = (1−2, 2−0, 0−1) = (−1, 2, −1).
  2. Upstream G = (1, 0, 2). Kernel: ∂J/∂k₀ = 1·1 + 0·2 + 2·0 = 1; ∂J/∂k₁ = 1·2 + 0·0 + 2·1 = 4.
  3. Input: ∂J/∂x₁ is used by z₀ (weight −1) and z₁ (weight 1): 1·(−1) + 0·1 = −1.
  4. Shared bias: ∂J/∂b = 1 + 0 + 2 = 3.

9.7 · Data types

What data suits a CNN?

Grid data: several channels observed at points in space or time. A CNN can also take inputs of different sizes — something a fixed-size weight matrix simply cannot — as long as the size varies because there is more of the same kind of observation.

Single channelMultichannel
1-DAudio waveform (amplitude over time)Skeleton animation (joint angles over time)
2-DFourier-transformed audio (frequency × time)Colour image (R, G, B over x, y)
3-DVolumetric data, e.g. CT scansColour video (channels over time, x, y)

In plain words

  • Images of different widths and heights: the kernel is simply applied a different number of times, and the output scales accordingly (a different-size doubly block circulant matrix, same kernel).
  • Need a fixed-size output (e.g. class scores)? Add a pooling layer whose regions scale with the input size.
  • Doesn’t make sense: inputs whose size varies because they optionally include different kinds of observations (college applications with or without a test score) — convolving the same weights over grades and test scores is meaningless.

Calculation, step by step

  1. Lengths 11 and 20, kernel 3: feature maps of 9 and 18.
  2. Pooling into quarters: regions of ~2 and ~4–5 values → always 4 numbers.
  3. So a classifier with 4 × C inputs works for both lengths.

Putting it together

A complete CNN and its training loop

Stack conv → ReLU → pool blocks, then a fully connected softmax layer. Everything else from the course trains it: cross-entropy loss, back-propagation (with transposed convolutions), SGD/Adam, careful initialization, augmentation, dropout and batch norm.

\[ \text{params(conv)}=k\cdot k\cdot C_{\text{in}}\cdot C_{\text{out}}+C_{\text{out}} \] \[ \text{cost}=H_{\text{out}}W_{\text{out}}\cdot k\cdot k\cdot C_{\text{in}}\cdot C_{\text{out}} \]

In plain words

  • Convolutional networks were some of the first deep networks to work with back-propagation — possibly just because they were computationally efficient, so it was easier to experiment and tune them.
  • They specialize neural nets for clear grid-structured topology and scale to very large models; most successful on 2-D images.
  • Early layers: small receptive fields, simple features (edges). Later layers: large receptive fields, complex features (parts, objects).
  • For 1-D sequences, the next specialization is the recurrent neural network.

Calculation, step by step

  1. Conv 1: 5×5, 3 → 16 channels: 5·5·3·16 + 16 = 1 216 parameters; same padding keeps 32×32.
  2. Pool → 16×16×16. Conv 2: 5·5·16·32 + 32 = 12 832. Pool → 8×8×32 = 2 048 values.
  3. FC to 10 classes: 2 048·10 + 10 = 20 490. Total ≈ 34 538 parameters.
  4. Receptive field: 5 → pool 6 → conv 6 + 4·2 = 14 → pool 16.

Wrap-up

Summary: how it all connects

Convolution = sparse + shared weights → equivariance; pooling adds invariance and downsampling. Together they are a strong prior that makes networks for grid data small, fast and data-efficient — or underfit when the prior is wrong.
