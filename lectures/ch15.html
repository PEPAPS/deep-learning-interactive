Transfer learning and domain adaptation

Deep networks need a lot of data — but much of what they learn on one problem is reusable on another. Transfer learning exploits what was learned in one setting (distribution P₁) to generalize better in another (P₂). Its relatives are domain adaptation (same task, shifted inputs), concept drift (shift over time) and multitask learning (one representation, several tasks). At the extreme it allows learning from one example — or from none.

Where transfer learning fits in training

Transfer learning changes the starting point of the loop: instead of random weights, the second task starts from a representation already learned on the first. 15.2 · Transfer learning and domain adaptation

Two settings, one shared explanation

Transfer learning and domain adaptation refer to the situation where what has been learned in one setting (distribution \(P_1\)) is exploited to improve generalization in another setting (distribution \(P_2\)). The assumption: many of the factors that explain the variations in \(P_1\) are relevant to the variations that need to be captured for \(P_2\).

\[ \text{learn on } P_1\ (\text{lots of data})\ \longrightarrow\ \text{reuse on } P_2\ (\text{little data}) \]the transfer setting \[ \text{transfer: same input kind, new targets}\qquad \text{adaptation: same task, shifted inputs} \]the two main flavours

In plain words

  • You learned to tell cats from dogs on 10 000 photos. Now you must tell ants from wasps with 20 photos. The categories are new, but “photo-ness” — edges, shapes, lighting, geometry — is the same. That shared part is what transfers.
  • Transfer learning is typically understood in a supervised context: the input is the same kind but the target is of a different nature (new visual categories).
  • Domain adaptation: the task and the optimal input-to-output mapping stay the same, but the input distribution is slightly different (book reviews → electronics reviews).
  • Both work through representation learning: a representation whose features correspond to underlying factors that appear in more than one setting.

Terms on this slide

Setting
A task together with its data distribution.
P₁, P₂
The data distributions of the first (source) and second (target) setting.
Transfer learning
Using knowledge from P₁ to generalize better on P₂.
Domain adaptation
Same task, different input distribution.
Factors of variation
The underlying causes that make inputs differ (pose, lighting, topic…).
Representation
The features h = f(x) a network computes from the input.

Calculation, step by step

  1. A convolutional net for P₁ has 1 000 000 weights and 10 000 labeled photos: 100 weights per example — fine with regularization.
  2. P₂ has 20 labeled photos. Training the same net from scratch: 50 000 weights per example — hopeless.
  3. Reuse the network up to its 64-dimensional representation and train only a new output layer: 64 × 2 + 2 = 130 weights for 20 examples — about 6 weights per example. Feasible.

15.2 · Transfer learning and domain adaptation

Why it works: shared low-level factors, and a lot of P₁ data

If there is significantly more data in the first setting, it can help to learn representations that let us quickly generalize from only very few examples drawn from \(P_2\). Many visual categories share low-level notions of edges and visual shapes, the effects of geometric changes, changes in lighting, and so on.

\[ \mathbf h=f(\mathbf x)\ \text{learned on } P_1,\qquad \hat y_2=\text{simple classifier}(\mathbf h)\ \text{fit on a few } P_2 \text{ examples} \]reuse the representation, learn only the new mapping

In plain words

  • Raw pixels of ants and wasps overlap hopelessly: lighting and pose vary more than the species. A representation trained on cats and dogs already factors out lighting and pose, so in that space the new classes form tight, separate clusters.
  • In a space where classes are tight clusters, even a very simple classifier — “which labeled example is closest?” — works, and it needs only a handful of labels.
  • Transfer learning, multitask learning and domain adaptation can all be achieved via representation learning when there exist features useful for the different settings, corresponding to underlying factors that appear in more than one setting.
  • If P₁’s factors are not relevant to P₂, nothing transfers (slide the relevance to 0 in the demo).

Terms on this slide

Low-level features
Edges, corners, textures — computed in the first layers.
Nearest-centroid classifier
Predict the class whose average labeled example is closest.
Few-shot
Learning a class from a small number n of labeled examples.
Cluster spread
How far the examples of one class scatter around their centre.

Calculation, step by step

  1. Three new classes, n = 2 labeled examples each. Learned features: class centres estimated from the 2 points, e.g. c₁ = (−1.3, 1.0), c₂ = (1.4, 0.9), c₃ = (0.1, −1.4).
  2. A test point (1.2, 0.7): distances² = 6.3, 0.08, 5.6 → class 2. With cluster spread 0.3 almost every test point lands near its own centre: ≈ 100 % accuracy.
  3. Raw pixels, spread 1.05: the same two labeled points give centre estimates off by ≈ 0.7 and the clusters overlap: ≈ 60 % accuracy.

15.2 · Transfer learning and domain adaptation

Share the bottom — or the top

Sometimes what is shared is not the semantics of the input but the semantics of the output. A speech recognizer must produce valid sentences for every speaker, but its early layers must handle very different versions of the same phonemes depending on who is speaking. Then it makes more sense to share the upper layers (near the output) and have task-specific preprocessing.

\[ \text{input semantics shared}\Rightarrow\text{share lower layers}\qquad \text{output semantics shared}\Rightarrow\text{share upper layers} \]a rule of thumb

In plain words

  • A network is a pipeline: early layers describe the input (edges → shapes → parts), late layers describe the output (parts → category). Share whichever end is the same in both settings.
  • Vision, new categories: the input is still photos → keep the lower layers, retrain the top.
  • Speech, new speaker: the output is still sentences → keep the upper layers, give each speaker (or group) its own input processing.
  • Reused layers can be frozen (not updated) or fine-tuned (updated gently). Frozen layers cost no P₂ data at all.

Terms on this slide

Lower / upper layers
Layers near the input / near the output.
Semantics of the input
What the raw input means (photos look alike).
Semantics of the output
What the output must be (valid sentences).
Phoneme
A basic sound unit of speech.
Frozen layer
Reused weights that are not changed during the second training.
Fine-tuning
Continuing to train reused weights with a small learning rate.

Calculation, step by step

  1. Layers 256 → 192 → 128 → 96 → 64 → 32 → 10. Weights per layer = in × out + out: 49 344, 24 704, 12 384, 6 208, 2 080, 330 (total 95 050).
  2. Vision (reuse the first four): train 2 080 + 330 = 2 410 weights on P₂; 92 640 (97 %) come from P₁.
  3. Speech (reuse the last four): train 49 344 + 24 704 = 74 048 weights for the new speaker’s input processing; the 21 002 weights that turn features into sentences are shared.

15.2 · Transfer learning and domain adaptation

Domain adaptation: same task, shifted inputs

In domain adaptation the task (and the optimal input-to-output mapping) remains the same between settings, but the input distribution is slightly different. Sentiment analysis: a predictor trained on reviews of books, videos and music is later used on comments about televisions or smartphones. There is an underlying function that tells whether any statement is positive, neutral or negative — but the vocabulary and style vary from one domain to another.

\[ P_1(\mathbf x)\neq P_2(\mathbf x),\qquad P_1(y\mid\mathbf x)=P_2(y\mid\mathbf x) \]inputs shift, the mapping does not

In plain words

  • “Gripping plot” and “crisp screen” are both praise, but a model that learned praise from book reviews has never seen “crisp”. The words shifted; the meaning of positive did not.
  • A shift along a direction the classifier ignores (style) is harmless; a shift along the direction it uses (vocabulary for “good”) moves the classes across the old boundary.
  • Adaptation can use no labels (align the statistics of the two domains, e.g. re-center the features) or a few labels from the target domain (fine-tune). Both are cheap because the task is unchanged.

Terms on this slide

Domain
A source of inputs with its own distribution (books vs. electronics).
Source / target domain
Where the model was trained / where it will be used.
Input distribution P(x)
Which inputs occur, and how often.
Decision boundary
The line where the classifier switches from one class to the other.
Re-centering
Shifting the target features so their mean matches the source mean.

Calculation, step by step

  1. Source classes centred at (+1, 0) and (−1, 0); the learned boundary is f₁ = 0 (feature 2 does not matter).
  2. Target shifted by (0.3, 1.4): centres (1.3, 1.4) and (−0.7, 1.4). The boundary f₁ = 0 still separates them well: the style shift is harmless.
  3. Target shifted by (1.5, 0): centres (2.5, 0) and (0.5, 0) — both on the positive side: accuracy ≈ 50 %. Re-centering subtracts the estimated shift (1.5, 0): boundary f₁ = 1.5 → back to ≈ 96 %.

15.2 · Transfer learning and domain adaptation

Concept drift: the slow version

Concept drift is gradual change of the data distribution over time — a form of transfer learning in which the second setting is the first one, a little later. Both concept drift and transfer learning can be viewed as particular forms of multitask learning.

\[ P_{t}\ \to\ P_{t+1}\ \to\ P_{t+2}\ \to\cdots \qquad \text{each month a slightly different } P_2 \]drift = a sequence of small transfers

In plain words

  • Spam changes its wording, customers change their habits, sensors age. A model trained once keeps its old boundary while the data walk away from it.
  • The training assumption of L1 — examples are i.i.d. from one fixed distribution — is violated slowly. Accuracy decays slowly too, which makes drift easy to miss.
  • Treat it as transfer: keep the representation, refresh the model with recent data regularly (or continuously). How often depends on how fast the data move.

Terms on this slide

Concept drift
Gradual change of P(x) or P(y | x) over time.
i.i.d.
Independent and identically distributed — the usual assumption about training data (L1).
Retraining schedule
How often the model is refit on recent data.

Calculation, step by step

  1. Class centres rotate 4° per month. After 12 months: 48°; the month-0 boundary is 48° off.
  2. With centres 1.1 away from the origin and spread 0.5, the accuracy of the month-0 model drops from ≈ 99 % to ≈ 88 % at month 12 and toward 50 % by month 24.
  3. Retraining every 6 months keeps the boundary within 20° of the truth: accuracy stays above ≈ 95 % all year.

15.2 · Transfer learning and domain adaptation

Multitask learning: one representation, several tasks

The objective of multitask learning is to take advantage of data from the first setting to extract information that may be useful when learning — or even when directly making predictions — in the second setting. Using the same representation in both settings allows the representation to benefit from the training data available for both tasks.

\[ J(\boldsymbol\theta_{\text{shared}},\boldsymbol\theta_A,\boldsymbol\theta_B)=J_A+J_B \]the shared parameters get gradients from both losses \[ \text{std. error alone}=\frac{\sigma}{\sqrt{n_B}}\qquad \text{shared}=\frac{\sigma}{\sqrt{n_A+n_B}} \]toy model: estimating a shared quantity

In plain words

  • Architecture: a shared trunk computes the representation; each task has its own small head. The total loss is the sum of the task losses, so every example of every task improves the trunk.
  • Why it helps: the trunk’s parameters are estimated from all the data (statistical strength), while each head only needs its own data. Task B with 8 examples “borrows” the 120 examples of task A for the shared part.
  • Transfer learning is multitask learning done sequentially; concept drift is multitask learning spread over time.

Terms on this slide

Trunk / head
The shared layers / the task-specific output layers.
Statistical strength
Precision gained by estimating one quantity from more examples.
Standard error
Typical error of an estimate: σ/√n for an average of n noisy values.
J_A, J_B
The losses of the two tasks.

Calculation, step by step

  1. Noise σ = 1 per example. Task B alone, n_B = 8: standard error 1/√8 = 0.354.
  2. Shared with task A, n_A = 120: 1/√128 = 0.088 — four times more precise.
  3. The gain is √((n_A + n_B)/n_B) = √16 = 4. With n_A = 0 there is nothing to borrow and the gain is 1.

15.2 · Transfer learning and domain adaptation

One-shot learning: a single labeled example

Two extreme forms of transfer learning are one-shot and zero-shot learning. In one-shot learning only one labeled example of the transfer task is given per class. It is possible because the representation learned in the first stage cleanly separates the underlying classes: during transfer, one labeled example is enough to infer the label of the many test examples that cluster around the same point in representation space.

\[ \hat y(\mathbf x)=y_{j^*},\qquad j^*=\arg\min_j\big\|f(\mathbf x)-f(\mathbf x_j)\big\| \]nearest labeled example in representation space

In plain words

  • Show a child one picture of an okapi and it will recognize okapis — because it already has a representation of animals in which “okapi-like” is a tight region. The network needs the same: a good first-stage representation.
  • With one labeled point per class, the classifier is simply “which labeled example is closest?”. It works when each class is one tight cluster, and fails when clusters overlap (switch the representation quality in the demo).
  • The labeled example does not teach the representation anything — it only names a cluster that already existed.

Terms on this slide

One-shot learning
Learning to recognize a class from a single labeled example.
Representation space
The space of feature vectors f(x).
Cluster
A tight group of points of the same class.
Nearest-neighbour rule
Copy the label of the closest labeled example.

Calculation, step by step

  1. Labeled examples (one per class) at A = (−1.3, 1.2), B = (1.6, 0.8), C = (0.1, −1.5).
  2. Test point (1.4, 1.0): distances to A, B, C = 2.71, 0.28, 2.82 → class B.
  3. With cluster spread 0.35 nearly every point is closer to its own class’s example (≈ 97 % agree); with spread 1.0 the clusters overlap and only ≈ 60 % do.

15.2 · Transfer learning and domain adaptation

Zero-shot learning: no labeled example at all

In zero-shot (zero-data) learning no labeled examples of the new classes are given. Consider a learner that reads a large collection of text and then solves object recognition: having read that a cat has four legs and pointy ears, it might guess that an image is a cat without having seen a cat. This is only possible because additional information was exploited during training.

\[ \mathbf x\ \xrightarrow{\ \text{trained detector}\ }\ \hat{\mathbf a}\ (\text{attributes})\qquad \hat y=\arg\max_{c}\ \text{match}\big(\hat{\mathbf a},\ \mathbf a_c^{\text{text}}\big) \]image → attributes → best-matching description

In plain words

  • Split recognition in two: (1) image → attributes (legs, stripes, wings…), learned from the classes we do have images of; (2) attributes → class, taken from text descriptions, which exist for classes we have never seen.
  • A zebra photo yields “four legs, hooves, stripes, black & white”. No zebra image was ever shown, but the description matches — and nothing else does.
  • The extra information (text) is a second modality linked to the first through shared attributes: the same idea as linking two languages on the next slide.

Terms on this slide

Zero-shot / zero-data learning
Recognizing classes with no labeled training examples.
Attribute
A describable property (four legs, stripes) shared across classes.
Seen / unseen class
A class with / without training images.
Description
The attribute vector of a class, obtained from text.
Match score
How many attributes agree between the detection and a description.

Calculation, step by step

  1. 12 attributes. Detected in the photo: {four legs, fur, hooves, stripes, black & white, large}.
  2. Agreement with each description (present in both or absent in both): zebra 12/12, horse 10/12 (no stripes, not black & white), giraffe 9/12, cat 7/12.
  3. Best match: zebra — an unseen class. If the detector misses “stripes”, zebra and horse tie at 11/12: zero-shot accuracy depends on reliable attribute detection.

15.2 · Transfer learning and domain adaptation

Linking two spaces: translating a word never seen translated

In machine translation we may have no example translating word A in language X to word B in language Y — yet we can guess a translation, because we learned a distributed representation for the words of each language and then created a link (possibly two-way) between the two spaces from matched sentence pairs. The transfer is most successful when the two representations and the relations between them are learned jointly.

\[ \mathbf y\approx\mathbf W\mathbf x+\mathbf b\quad\text{fit on matched pairs }(\mathbf x_i,\mathbf y_i) \]a linear link between the English space and the Spanish space \[ \text{translation}(w)=\arg\min_{w'}\big\|\mathbf W\mathbf x_w+\mathbf b-\mathbf y_{w'}\big\| \]map across, then take the nearest neighbour

In plain words

  • In each language, words with related meanings sit near each other: animals together, numbers together, colours together. The two “maps” have the same shape, only rotated, scaled and shifted.
  • A few matched pairs (cat–gato, king–rey, one–uno) are enough to fit the rotation/scale/shift. Then every English word can be carried across and matched to its nearest Spanish word — including words that never appeared in a pair.
  • The same mechanism links images to text (zero-shot learning), speech to text, and so on.

Terms on this slide

Distributed representation
A word as a vector of many features, so similar words are nearby.
Anchor / matched pair
A word pair known to be translations, used to fit the link.
Linear map W, b
Rotation/scaling (W) and shift (b) from one space to the other.
Least squares
Choose W, b to minimize Σ‖Wxᵢ + b − yᵢ‖² over the anchors (L3).
Nearest neighbour
The Spanish vector closest to the mapped English vector.

Calculation, step by step

  1. Spanish space = English space rotated 35°, scaled 1.1, shifted by (0.4, −0.2). Three anchors fix the 6 numbers of W and b by least squares.
  2. “dog” = (1.4, 0.7). The map fit on three anchors is x′ = 1.00x − 0.61y + 0.43, y′ = 0.51x + 1.02y − 0.30, so “dog” lands at (1.00·1.4 − 0.61·0.7 + 0.43, 0.51·1.4 + 1.02·0.7 − 0.30) = (1.41, 1.13).
  3. Nearest Spanish vector to (1.41, 1.13): “perro” at distance 0.21 — correct, although dog–perro was never a training pair.

Wrap-up

Summary: how it all connects

All of these are the same move: find a representation whose features are shared across settings, learn it where data are plentiful, and reuse it where they are scarce. The less that changes between settings, the less new data you need — down to one example, or none if a description can stand in for it.
