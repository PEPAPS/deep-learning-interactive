Lecture 12 · Chapter 14

Autoencoders: learning by copying

An autoencoder is a network trained to copy its input to its output — through a code in the middle. The trick is to make perfect copying impossible (a small code, a sparsity penalty, noisy inputs, or a derivative penalty) so that the network must prioritize what to keep. What it keeps is a useful description of the data: features, a compression, a way to denoise, or a way to search.

Where autoencoders fit in training

An autoencoder is an ordinary feedforward network trained with the ordinary loop — the only differences are what the target is (the input itself, so no labels are needed), what the loss contains (reconstruction error plus, maybe, a penalty), and what we keep at the end (the code and the encoder, not the output).

From L4 and L5

Encoder and decoder are just layers; back-propagation trains them. “Autoencoders may be trained with all the same techniques.”

From L6

Sparsity penalties, noise and derivative penalties are regularizers — here they are what makes copying useful.

New here

Unsupervised learning: no labels, the data explain themselves. The code h becomes the product — a representation.

14 · Autoencoders

Encoder, code, decoder — and why copying is not useless

Two functions: an encoder \(\mathbf h = f(\mathbf x)\) that squeezes the input into a code, and a decoder \(\mathbf r = g(\mathbf h)\) that rebuilds the input. If it could learn \(g(f(\mathbf x))=\mathbf x\) everywhere it would be useless — so it is built to copy only approximately, and only inputs that resemble the training data.

\[ \mathbf h = f(\mathbf x) \qquad \mathbf r = g(\mathbf h) = g(f(\mathbf x)) \approx \mathbf x \]encoder · decoder · reconstruction

In plain words

  • Think of a game of “telephone” through a narrow pipe: whatever does not fit through the pipe (the code) cannot come out the other side. The network must decide what matters most about an input.
  • We usually do not care about the output r at all — we care about the code h and the encoder f, because to copy well, h must contain a compact, useful description of x.
  • Because it is forced to prioritize, an autoencoder “often learns useful properties of the data” — features for classification, a compression, a notion of similarity.
  • It is a special case of a feedforward network: the same layers, the same back-propagation, the same optimizers.

Terms on this slide

Autoencoder
A network trained to output a copy of its input.
Encoder f
The first half: input x → code h.
Code h
The hidden representation in the middle (also “latent representation”).
Decoder g
The second half: code h → reconstruction r.
Reconstruction r
The network’s attempt to copy x.
Identity function
g(f(x)) = x for every x — perfect copying, which teaches nothing.

Calculation, step by step

  1. Input x = (1, 1, 0.4, 0.4). Encoder with weights 0.5: h₁ = 0.5·1 + 0.5·1 = 1, h₂ = 0.5·0.4 + 0.5·0.4 = 0.4.
  2. Decoder repeats each code number: r = (1, 1, 0.4, 0.4). Loss Σ(xᵢ − rᵢ)² = 0 — copied.
  3. Input x = (1, −1, 0.5, −0.2): h = (0, 0.15), r = (0, 0, 0.15, 0.15). Loss = 1 + 1 + 0.1225 + 0.1225 = 2.245 — the within-pair differences did not fit through the code.

14 · Modern autoencoders

From functions to distributions

Modern autoencoders replace the deterministic functions by stochastic mappings \(p_{\text{encoder}}(\mathbf h\mid\mathbf x)\) and \(p_{\text{decoder}}(\mathbf x\mid\mathbf h)\). That connects autoencoders to latent-variable models and makes them generative: sample a code, decode it, and you get a new plausible input.

\[ \mathbf h\sim p_{\text{encoder}}(\mathbf h\mid\mathbf x) \qquad \mathbf x'\sim p_{\text{decoder}}(\mathbf x\mid\mathbf h) \]stochastic encoder and decoder

In plain words

  • A deterministic encoder answers “what is the code of x?” with one vector. A stochastic encoder answers with a probability distribution over codes — “probably around here”.
  • Likewise the decoder gives a distribution over inputs for a given code: the model can then generate data by sampling.
  • Traditionally autoencoders were used for dimensionality reduction and feature learning; the probabilistic view brought them “to the forefront of generative modeling” (variational autoencoders are the best-known example).
  • The deterministic autoencoder is the special case where both distributions put all their mass on one point (σ = τ = 0 in the demo).

Terms on this slide

Stochastic mapping
A rule that outputs a probability distribution instead of one value.
\(p_{\text{encoder}}(\mathbf h\mid\mathbf x)\)
Probability of code h given input x.
\(p_{\text{decoder}}(\mathbf x\mid\mathbf h)\)
Probability of input x given code h.
Latent variable
A hidden quantity (here h) that the model assumes explains the observed x.
Generative model
A model that can produce new samples of x.

Calculation, step by step

  1. Data lie on a curve parameterized by s ∈ [0, 1]; the code is the position s. Input x slightly off the curve → f(x) = nearest position, say h = 0.35.
  2. Stochastic encoder: p(h | x) = N(0.35, 0.05²). Sampling gives h′ = 0.35 + 0.05·z with z ~ N(0, 1), e.g. z = 1.2 → h′ = 0.41.
  3. Decoder: g(0.41) = the curve point at s = 0.41; stochastic version adds N(0, τ²) noise. Forty such samples form the orange cloud of “inputs like x”.

14.1 · Undercomplete autoencoders

Make the code smaller than the input

The simplest way to forbid perfect copying: give the code fewer dimensions than the input. Such an undercomplete autoencoder must capture the most salient features of the training data. Training just minimizes a reconstruction loss.

\[ L\big(\mathbf x,\ g(f(\mathbf x))\big) \](14.1) — L penalizes g(f(x)) for being dissimilar from x, e.g. mean squared error

In plain words

  • 64 pixels in, 16 numbers in the middle, 64 pixels out. To rebuild the picture from 16 numbers, those numbers must describe the picture’s main patterns.
  • The loss L measures how different the output is from the input; with real-valued inputs the usual choice is the mean squared error.
  • Copying may “sound useless”, but we are not interested in the output — we hope that solving the copying task makes h take on useful properties.
  • In the demo, images made of bars are copied well even with a tiny code, while a diagonal stroke (never in the training set) is not: the autoencoder copies only what resembles its training data.

Terms on this slide

Undercomplete
Code dimension smaller than input dimension.
Code dimension
The number of numbers in h.
Loss function L
A measure of dissimilarity between x and its reconstruction.
Mean squared error
Average of (xᵢ − rᵢ)² over the components.
Salient features
The aspects of the data that explain most of the variation.

Calculation, step by step

  1. Input x has 64 pixels; code size k = 16 → compression 64/16 = 4×. The 16 numbers keep 98.7 % of the variance of the training images.
  2. Reconstruction r; MSE = (1/64)·Σᵢ(xᵢ − rᵢ)². If 63 pixels are exact and one is off by 0.3: MSE = 0.09/64 = 0.0014 — the 72 training images score 0.0015 on average.
  3. The diagonal stroke (never seen in training) scores 0.123 — about 80 times worse: the code has no room for diagonals, only for bars.

14.1 · Undercomplete autoencoders

With a linear decoder and MSE, the autoencoder learns PCA

When the decoder is linear and L is the mean squared error, an undercomplete autoencoder learns to span the same subspace as PCA: it finds the principal subspace of the training data as a side effect of copying. Nonlinear encoders and decoders learn a more powerful, nonlinear generalization of PCA.

\[ \mathbf h = \mathbf V_k^{\top}(\mathbf x-\boldsymbol\mu),\qquad \mathbf r=\boldsymbol\mu+\mathbf V_k\mathbf h \]linear encoder and decoder (V_k = k orthonormal directions) \[ J=\sum_{\text{examples}}\|\mathbf x-\mathbf r\|^2 \ \text{ is minimized when } \mathbf V_k=\text{top-}k\text{ principal directions} \]PCA = the k directions of largest variance

In plain words

  • With one code number and 2-D data, the decoder can only produce points on a line. The reconstruction of x is the closest point on that line; the error is the perpendicular distance.
  • Turning the line to minimize the total squared error gives the direction along which the data vary the most — the first principal component. Gradient descent on the copying loss finds it automatically.
  • If the data lie on a curve, no line fits well. A nonlinear encoder/decoder can use the curve itself as its 1-number code — this is what makes nonlinear autoencoders more powerful than PCA.

Terms on this slide

PCA
Principal component analysis: the orthogonal directions of largest variance.
Principal subspace
The space spanned by the top-k principal directions.
Span
All points reachable as combinations of some directions.
Linear decoder
r is a linear (matrix) function of h.
μ
The mean of the training data.

Calculation, step by step

  1. Line direction u = (cos θ, sin θ). For θ = 20°: u = (0.94, 0.34).
  2. Point x = (1.5, 0.9): code h = uᵀx = 0.94·1.5 + 0.34·0.9 = 1.72; reconstruction r = h·u = (1.62, 0.59); error ‖x − r‖² = 0.12² + 0.31² = 0.11.
  3. Add this over all points to get J(θ); the angle with the smallest J is the PCA direction (in the demo 31.8°). Gradient descent on θ gets there by itself.

14.1 · Undercomplete autoencoders

Too much capacity learns nothing

If encoder and decoder have too much capacity, the autoencoder copies without extracting anything useful. If the code is as large as the input (or larger — overcomplete), even a linear encoder and decoder can learn the identity and learn nothing about the data distribution.

\[ \dim(\mathbf h)\ \ge\ \dim(\mathbf x)\ \Rightarrow\ g(f(\mathbf x))=\mathbf x \text{ is reachable, with } L=0 \text{ for every } \mathbf x \]the identity trap

In plain words

  • A pipe as wide as the input lets everything through: data, but also pure noise. Zero reconstruction error on everything means the code has no opinion about what the data look like.
  • The warning sign is no gap between “copies my data” and “copies anything”. A useful autoencoder copies its data much better than random inputs.
  • Capacity is not only the code size: a very deep, very flexible encoder can hide a lot of information in a small code too (a one-dimensional code can in principle index every training example). Limiting capacity by hand is clumsy — the next part replaces it with regularization.

Terms on this slide

Capacity
How many different functions a model can represent (L1).
Overcomplete
Code dimension greater than input dimension.
Identity trap
Learning g(f(x)) = x exactly, which carries no information about the data.
Data distribution
p_data(x): which inputs are likely and which are not.

Calculation, step by step

  1. Linear autoencoder on 64-pixel images with k = 64: choose V = identity → h = x − μ, r = μ + h = x. MSE = 0 for every x, noise included.
  2. With k = 16: MSE ≈ 0.0045 on a training image, ≈ 0.068 on pure noise. The gap (×15) shows that the code encodes the structure of bar images.
  3. As k grows the noise error falls toward 0; the gap closes; at k = 64 nothing distinguishes data from noise.

  • Leads toregularized autoencoders — constrain the loss instead of the size.
14.2 · Regularized autoencoders

Constrain the loss, not the size

Instead of keeping the model shallow and the code small, regularized autoencoders use a loss that rewards other properties besides copying: sparsity of the code, small derivatives of the code, or robustness to noise. Then the model can be nonlinear and overcomplete and still learn something useful — even if it has enough capacity for the identity.

\[ J = \underbrace{L\big(\mathbf x,\ g(f(\mathbf x))\big)}_{\text{copy well}} \;+\; \underbrace{\Omega(\mathbf h,\mathbf x)}_{\text{…but have another property}} \]the general shape of a regularized autoencoder

In plain words

  • Three recipes, each of which gives the network a reason not to be the identity:
  • Sparse: add a penalty so that only a few code units are active for each input.
  • Denoising: feed a corrupted input but demand the clean one back — copying would reproduce the damage.
  • Contractive: penalize how fast the code changes when the input changes a little.
  • All three are regularizers in the sense of L6: they trade a little training error for a representation that generalizes.

Terms on this slide

Regularized autoencoder
An autoencoder whose loss encourages properties beyond copying.
Ω
A penalty term added to the loss (L6 notation).
Sparsity
Most code units are exactly zero.
Robustness to noise
The output does not change much when the input is corrupted.

Calculation, step by step

  1. Plain: J = L(x, g(f(x))). With k ≥ dim x the best J is 0 — identity.
  2. Sparse: J = L + λΣ|hᵢ|. The identity needs all units → large Ω; a sparse code with a slightly worse L can win. For λ = 0.5 and 12 units of size 1: Ω = 6, so any copying scheme with Ω < 6 that loses less than 6 in L is preferred.
  3. Denoising: J = L(x, g(f(x̃))). The identity gives L = ‖x̃ − x‖² = the noise energy (e.g. 64 × 0.1 = 6.4 for σ ≈ 0.3) — a denoiser can do much better.

14.2.1 · Sparse autoencoders

Sparse autoencoders: few units may speak

A sparse autoencoder adds a sparsity penalty \(\Omega(\mathbf h)\) on the code layer to the reconstruction error. To keep the penalty small, only a few code units can be non-zero for any input — so each unit must respond to a specific statistical feature of the dataset instead of helping to copy everything.

\[ L\big(\mathbf x,\ g(f(\mathbf x))\big) + \Omega(\mathbf h) \](14.2) — h = f(x) is the encoder output, g(h) the decoder output \[ \Omega(\mathbf h)=\lambda\sum_i |h_i| \](14.3) — the L¹ penalty on the code

In plain words

  • Imagine 1 000 code units but only ~20 are allowed to light up per image. Each unit becomes a detector for something that actually occurs in the data (a bar at column 3, a curve, a texture).
  • The penalty is the L¹ norm of the code, not of the weights as in L6. Its effect is the same kind: many values become exactly zero (soft thresholding).
  • Sparse autoencoders are typically used to learn features for another task, such as classification.
  • An autoencoder regularized to be sparse must respond to the unique statistical features of its dataset rather than act as an identity function.

Terms on this slide

Sparsity penalty Ω(h)
A cost that grows with the number and size of non-zero code units.
λ
How strongly sparsity is enforced.
L¹ norm Σ|hᵢ|
Sum of absolute values; it pushes values to exactly 0.
Soft threshold
sign(a)·max(|a| − λ, 0): shrink by λ, cut at 0.
Active unit
A code unit whose value is not 0.

Calculation, step by step

  1. Suppose reconstruction alone wants unit values a = (1.6, −0.2, 0.9, 0.15, …). For one unit the cost is ½(a − h)² + λ|h|; its minimizer is the soft threshold.
  2. λ = 0.5: h₁ = 1.6 − 0.5 = 1.1; h₂ = 0 (|−0.2| ≤ 0.5); h₃ = 0.4; h₄ = 0.
  3. Ω(h) = 0.5 × (1.1 + 0.4 + …) and only the strong units stay active. Raising λ switches off more units.

14.2.1 · Sparse autoencoders

Why sparsity: a prior on latent variables

The sparse autoencoder can be seen as approximate maximum-likelihood training of a generative model with latent variables h: the joint is \(p_{\text{model}}(\mathbf h,\mathbf x)=p_{\text{model}}(\mathbf h)\,p_{\text{model}}(\mathbf x\mid\mathbf h)\), and the prior \(p_{\text{model}}(\mathbf h)\) is what the sparsity penalty really is: with a Laplace prior, \(-\log p(\mathbf h)\) is exactly \(\lambda\sum_i|h_i|\) plus a constant. The features are useful because they describe the latent variables that explain the input.

\[ \log p_{\text{model}}(\mathbf h,\mathbf x)=\log p_{\text{model}}(\mathbf h)+\log p_{\text{model}}(\mathbf x\mid\mathbf h) \](14.5) — prior × likelihood \[ p_{\text{model}}(h_i)=\frac{\lambda}{2}e^{-\lambda|h_i|} \](14.6) — Laplace prior on each unit \[ -\log p_{\text{model}}(\mathbf h)=\sum_i\Big(\lambda|h_i|-\log\frac{\lambda}{2}\Big)=\Omega(\mathbf h)+\text{const} \](14.7–14.8)

In plain words

  • The prior p(h) is the model’s belief about codes before seeing x. A Laplace prior says “most code units are probably near zero”.
  • Maximizing log p(x | h) + log p(h) means: explain x well (reconstruction) and use a code the prior finds plausible (sparse). That is the MAP idea of L2 applied to the code instead of the weights.
  • The constant −log(λ/2) does not depend on h, so it does not change the training — only the λ|hᵢ| term matters.
  • A Gaussian prior would give h² instead of |h|: it shrinks units but rarely makes them exactly zero. The kink of |h| at 0 is what creates true sparsity.

Terms on this slide

Prior p(h)
Beliefs about the latent variables before observing x.
Likelihood p(x | h)
How probable x is given the code h (the decoder).
Laplace distribution
Density (λ/2)e^(−λ|h|): a sharp peak at 0 with heavy tails.
Maximum likelihood
Choose the model that makes the data most probable (L2).
Latent variables
Unobserved causes that explain the input.

Calculation, step by step

  1. λ = 1.5, one unit with h = 0.8: p(h) = 0.75·e^(−1.2) = 0.226.
  2. −log p(h) = 1.5 × 0.8 − log 0.75 = 1.2 + 0.288 = 1.488 = λ|h| + 0.288.
  3. The 0.288 is the same for every h, so minimizing −log p(h) over h means minimizing λ|h|: the L¹ penalty.

14.2.2 · Denoising autoencoders

Denoising autoencoders: undo the damage

Rather than adding a penalty, change the reconstruction term: feed a corrupted copy \(\tilde{\mathbf x}\) of the input but ask for the clean \(\mathbf x\) back. A denoising autoencoder (DAE) must therefore undo the corruption rather than simply copy — and to do that it must learn what clean data look like.

\[ L\big(\mathbf x,\ g(f(\tilde{\mathbf x}))\big) \](14.9) — x̃ is a copy of x corrupted by some form of noise

In plain words

  • Show the network a smudged photo and grade it against the clean photo. The identity function gets a bad grade (it returns the smudges), so copying is no longer the best strategy.
  • To remove noise you must know what the signal normally looks like — bars, faces, words. So denoising training “forces f and g to implicitly learn the structure of p_data(x)”.
  • Another example of useful properties emerging as a by-product of minimizing reconstruction error.
  • It shows how overcomplete, high-capacity models can be used as autoencoders, as long as they are prevented from learning the identity.
  • Typical corruptions: Gaussian noise added to every pixel, or “masking” (setting a random subset of inputs to 0).

Terms on this slide

Corruption
A random process C(x̃ | x) that damages x.
x̃ (x-tilde)
The corrupted copy of x that the encoder sees.
Masking noise
Setting a random fraction of the inputs to 0.
Gaussian noise
Adding N(0, σ²) to each input.
Denoising
Recovering the clean x from x̃.

Calculation, step by step

  1. Clean x (64 pixels). Corrupt with σ = 0.35 Gaussian noise (pixel values clipped to [0, 1]): ‖x̃ − x‖²/64 = 0.042 — this is what plain copying would score.
  2. Encode x̃ with the k = 16 bar autoencoder and decode: the code can only express bar patterns, so most of the random noise is dropped: ‖g(f(x̃)) − x‖²/64 = 0.017.
  3. Error reduced by ≈ 60 %. With k = 64 nothing is dropped: the error stays at 0.042 (identity trap).

14.2.2 · Denoising autoencoders

What a denoising autoencoder learns: pointing back to the data

Picture the data as living near a thin manifold (a curve in the demo). Corrupted inputs sit off the manifold; the DAE learns to map each of them back to the nearest point of the data. The difference \(r(\tilde{\mathbf x})-\tilde{\mathbf x}\) forms a vector field pointing toward high data density — an implicit description of \(p_{\text{data}}(\mathbf x)\).

\[ g(f(\tilde{\mathbf x}))-\tilde{\mathbf x}\ \approx\ \text{direction toward the data manifold} \]the reconstruction vector field of a DAE

In plain words

  • Every training pair is “here is a damaged point, here is where it came from”. Averaged over many pairs, the network learns where the data are around every nearby location.
  • The arrows are only reliable near the data (within roughly the noise size): the DAE never saw points far away.
  • The DAE makes the reconstruction function resist small but finite perturbations of the input — exactly the size of the training noise.
  • This is why DAEs capture the structure of the data distribution: the field tells you how to move any point to make it “more typical”.

Terms on this slide

Manifold
A low-dimensional surface (here a curve) along which the data vary.
Vector field
An arrow attached to every point of the space.
Density p_data(x)
How likely each region of input space is.
Finite perturbation
A small but non-zero displacement of the input.

Calculation, step by step

  1. Clean training point x = (0.30, 0.72) on the curve; corruption ε = (0.00, +0.08) gives x̃ = (0.30, 0.80).
  2. The target is x, so the ideal output is r(x̃) = (0.30, 0.72): r(x̃) − x̃ = (0, −0.08) — an arrow pointing straight back to the curve.
  3. Collect this arrow for every corrupted point: a field that is zero on the curve and points toward it nearby.

14.2.3 · Contractive autoencoders

Contractive autoencoders: penalize the derivatives

Keep the penalty Ω, but make it about derivatives: ask the code \(\mathbf h=f(\mathbf x)\) to change as little as possible when x changes slightly. The penalty is the squared Frobenius norm of the Jacobian of the encoder. Because it is applied only at training examples, the encoder learns features that capture information about the training distribution.

\[ \Omega(\mathbf h,\mathbf x)=\lambda\sum_i\big\|\nabla_{\mathbf x}h_i\big\|^2 \](14.11) — sum over code units of the squared gradient \[ \Omega(\mathbf h)=\lambda\left\|\frac{\partial f(\mathbf x)}{\partial\mathbf x}\right\|_F^2 \](14.18) — the same thing written with the Jacobian matrix

In plain words

  • The Jacobian ∂f/∂x is a table: entry (i, j) says how much code unit i moves when input j moves. The Frobenius norm squares and adds all entries.
  • Making it small means a neighbourhood of inputs is mapped to a smaller neighbourhood of codes — the space is contracted. Hence the name.
  • But the code must still differ between different training examples (to reconstruct them), so it contracts mostly in directions across the data manifold and keeps sensitivity along it.
  • The penalty needs the derivative ∂f/∂x inside the loss, so training needs derivatives of derivatives — back-propagation handles it.

Terms on this slide

Contractive autoencoder (CAE)
An autoencoder with the Jacobian penalty.
Jacobian ∂f/∂x
Matrix of all partial derivatives ∂hᵢ/∂xⱼ (L3).
Frobenius norm ‖·‖_F
Square root of the sum of squared matrix entries.
Infinitesimal perturbation
An arbitrarily small change of the input (a derivative measures the response to it).
Contraction
Mapping a neighbourhood to a smaller one.

Calculation, step by step

  1. Encoder h = tanh(Wx), W = [[1, 0.5], [−0.3, 1]], x₀ = (0.6, −0.3): Wx₀ = (0.45, −0.48), h = (0.42, −0.45).
  2. Jacobian = diag(1 − h²)·W: row 1 = (1 − 0.18)·(1, 0.5) = (0.82, 0.41); row 2 = (1 − 0.20)·(−0.3, 1) = (−0.24, 0.80).
  3. ‖J‖²_F = 0.82² + 0.41² + 0.24² + 0.80² = 0.67 + 0.17 + 0.06 + 0.64 = 1.54; Ω = λ·1.54. A smaller gain of W, or saturating tanh, shrinks it.

14.2.3 · Contractive autoencoders

Denoising and contractive: two sides of one idea

In the limit of small Gaussian input noise, the denoising reconstruction error is equivalent to a contractive penalty on the reconstruction function \(\mathbf x\mapsto g(f(\mathbf x))\). Denoising autoencoders resist small but finite perturbations of the reconstruction; contractive autoencoders resist infinitesimal perturbations of the features.

\[ \mathbb E_{\epsilon\sim N(0,\sigma^2)}\big[(r(x_0+\epsilon)-x_0)^2\big] \approx \big(r(x_0)-x_0\big)^2+\sigma^2\,r'(x_0)^2 \]denoising error ≈ reconstruction error + σ² × (derivative of r)²

In plain words

  • Average the denoising error over small noise and expand r around the clean point: you get the usual error plus σ² times the squared slope of r. The noise term is a derivative penalty — on r = g∘f, weighted by the noise variance.
  • So both recipes say: near the data, the function should barely react to small input changes. DAE does it statistically with finite noise; CAE does it analytically with the Jacobian, and only for the encoder f.
  • Both contract the space around the data; the denoising one additionally learns the vector field back to the manifold.

Terms on this slide

Reconstruction function
The whole map x ↦ g(f(x)).
Feature extraction function
The encoder f alone.
𝔼[·]
Expected value (average) over the random noise.
Taylor expansion
r(x₀ + ε) ≈ r(x₀) + r′(x₀)ε for small ε.

Calculation, step by step

  1. Near x₀ = 0 let r(x) = b + s·x with b = 0.2 (offset) and s = 0.6 (slope). Noise ε ~ N(0, σ²), σ = 0.6.
  2. (r(ε) − 0)² = (b + sε)² = b² + 2bsε + s²ε². Averaging: E[ε] = 0 and E[ε²] = σ², so E = b² + σ²s² = 0.04 + 0.36 × 0.36 = 0.04 + 0.13 = 0.17.
  3. Set the slope to 0: E = b² = 0.04. The noise term vanishes only when r is flat near the data — a contraction.

14.3 · Representational power, layer size and depth

Shallow or deep?

Autoencoders are often trained with a single-layer encoder and decoder, but deep ones have many advantages. One hidden layer can represent the identity along the data arbitrarily well, yet cannot easily enforce constraints such as sparsity. Experimentally, deep autoencoders yield much better compression than shallow or linear ones.

\[ \text{parameters of a weight layer}=n_{\text{in}}\times n_{\text{out}}+n_{\text{out}} \]counting what each design costs

In plain words

  • Linear (no hidden layer): only linear structure; PCA when the code is small, the identity when it is not.
  • One hidden layer per side: the universal approximation theorem (L4) says it can represent almost any encoder/decoder with enough units — but “almost any” includes the identity, and asking it to also be sparse or contractive is hard.
  • Deep: depth can reduce the computational cost and the amount of training data needed to represent some functions exponentially (L4). The same argument applies to encoders and decoders.
  • Deep autoencoders are often trained greedily, one shallow autoencoder at a time, then fine-tuned (pretraining, L9).

Terms on this slide

Shallow
One hidden layer.
Deep
Several hidden layers in the encoder and in the decoder.
Universal approximation
One wide hidden layer can approximate any continuous function (L4).
Compression
Representing x with far fewer numbers while keeping it reconstructable.

Calculation, step by step

  1. Linear, 64 → 8 → 64: encoder 64×8 + 8 = 520, decoder 8×64 + 64 = 576 — 1 096 parameters, only linear structure.
  2. Shallow, 64 → 32 → 8 → 32 → 64: 64·32 + 32 + 32·8 + 8 + 8·32 + 32 + 32·64 + 64 = 4 456 parameters, nonlinear.
  3. Deep, two hidden layers of 32 per side: adds 2 × (32·32 + 32) = 2 112 → 6 568 parameters, and a much richer family of encoders for the money.

14.8 · Applications of autoencoders

Dimensionality reduction: fewer numbers, better organized

Autoencoders are successfully applied to dimensionality reduction and information retrieval. A lower-dimensional representation can improve many tasks (e.g. classification): it places semantically related examples near each other, which helps generalization, and smaller spaces cost less memory and runtime.

\[ \mathbf x\in\mathbb R^{64}\ \xrightarrow{\ f\ }\ \mathbf h\in\mathbb R^{2}\qquad \text{similar } \mathbf x \Rightarrow \text{nearby } \mathbf h \]the code as a map of the dataset

In plain words

  • Plot every training image by its first two code numbers: the three kinds of image fall into three regions — and the autoencoder was never told the kinds.
  • A classifier that works in this 2-D space needs far fewer examples than one working on 64 raw pixels: the hints provided by the mapping aid generalization (recall the curse of dimensionality, L2).
  • Hinton & Salakhutdinov (2006) showed a deep autoencoder producing a 2-D code of documents that separates topics much better than the equivalent PCA.
  • Nearest neighbours in code space are a first form of retrieval: “find me things like this”.

Terms on this slide

Dimensionality reduction
Mapping x to a representation with fewer numbers.
Semantically related
Similar in meaning (same kind of object), not necessarily similar pixel by pixel.
Nearest neighbour
The stored example whose code is closest to the query’s code.
Generalization
Working on new examples (L1).

Calculation, step by step

  1. Image #11 has code h = (h₁, h₂) = (−0.17, −0.17). Image #50 has h′ = (−0.22, −0.15).
  2. Distance ‖h − h′‖ = √(0.05² + 0.02²) = 0.05 — tiny, so #50 is its nearest neighbour, and it is indeed the same kind of image (horizontal bars).
  3. Comparing 2 numbers instead of 64 pixels: 32× less memory and arithmetic per comparison.

14.8 · Applications of autoencoders

Information retrieval: semantic hashing

Information retrieval = finding database entries that resemble a query. If the autoencoder produces a code that is low-dimensional and binary, every entry can be stored in a hash table keyed by its code: retrieval returns all entries with the same binary code as the query — no distance computations at all.

\[ b_j=\mathbb 1[h_j>0],\quad j=1..m \qquad \text{key}=b_1b_2\cdots b_m \]binary code from the first m code numbers (threshold at 0)

In plain words

  • A hash table maps a key to a bucket in constant time. If similar inputs get the same binary code, the bucket is the search result.
  • Linear search compares the query with all N entries (N distance computations). Semantic hashing: compute the code once, look up one bucket.
  • Slightly less similar items live in buckets whose key differs by one or two bits — flipping bits of the query key (Hamming distance search) finds them cheaply too.
  • In practice the final layer uses sigmoids pushed to saturate at 0 or 1, so that the code is essentially binary; this demo simply thresholds the linear code.

Terms on this slide

Information retrieval
Finding stored items that resemble a query.
Hash table
A data structure that jumps straight to the bucket for a key.
Binary code
A vector of 0/1 bits.
Semantic hashing
Using a learned binary code as the hash key, so that one bucket holds similar items.
Hamming distance
Number of bits in which two codes differ.

Calculation, step by step

  1. Query code (first 3 numbers): h = (0.65, −0.89, −0.82) → bits (1, 0, 0) → key “100”.
  2. Bucket “100” holds 11 of the 72 images (the query included): returned with 1 lookup instead of 72 distance computations (each of 64 multiplications).
  3. With m = 3 bits there are 2³ = 8 buckets of ≈ 9 images; with m = 6, up to 64 buckets of ≈ 1–2 images — more selective.

Wrap-up

Summary: how it all connects

An autoencoder learns by copying under a constraint. The constraint is either a small code (undercomplete → PCA when linear) or a regularizer (sparse, denoising, contractive). Each constraint forces the code to capture the structure of the data, which is what we actually keep: features, a compression, a denoiser, or a hash key.

Remember

An autoencoder that copies everything perfectly has learned nothing. Useful properties appear as a by-product of copying under a constraint.
