Back-Propagation

Gradient descent needs \(\nabla_{\boldsymbol\theta}J\) for every weight. Writing the formula is easy; computing it cheaply is the problem. Back-propagation walks the network’s computational graph backwards, applying the chain rule once per edge and reusing stored results — so a full gradient costs about as much as one forward pass.

Where this lecture fits in training

Back-propagation is step 6 of the loop: after the forward pass has produced the loss, information flows backward to give the gradient that the optimizer (step 7) uses.

Forward propagation

x → hidden units → ŷ → scalar cost J(θ). Every intermediate value is remembered.

Back-propagation

From ∂J/∂J = 1, multiply by local derivatives (Jacobians) backwards through the graph, summing where paths merge.

Then learning

SGD, momentum, Adam … use ∇θJ to update θ. Backprop itself does not learn anything.

6.5 · Back-propagation

What back-propagation is — and what it isn’t

Backprop is only a way to compute the gradient, cheaply and exactly. It is not the learning algorithm (that’s SGD), and it is not specific to neural networks — it differentiates any function built from known operations.

\[ \text{goal: }\ \nabla_{\mathbf x}f(\mathbf x,\mathbf y)\quad\text{— in learning: }\ \nabla_{\boldsymbol\theta}J(\boldsymbol\theta) \]

In plain words

  • Forward propagation: x flows up through the hidden units to ŷ, and on to the scalar cost J(θ).
  • Back-propagation (“backprop”): information from the cost flows backward to compute the gradient.
  • An analytical gradient formula is easy to write but can be expensive to evaluate numerically; backprop is a simple, inexpensive procedure.
  • We want ∇ₓf(x, y) where x are the variables whose derivatives we need (the parameters) and y are other inputs whose derivatives we don’t need (e.g. the data).

Terms on this slide

Forward propagation
Computing outputs (and the cost) from inputs.
Back-propagation
Computing derivatives of the cost by going backwards.
Numerical gradient
Estimate via \((J(\theta+\epsilon)-J(\theta-\epsilon))/2\epsilon\) for each parameter — exact enough to check backprop, far too slow to train.
Gradient check
Comparing backprop to the numerical gradient to catch bugs.

Calculation, step by step

  1. A network with 1 000 000 weights. Numerical gradient: 2 forward passes per weight → 2 000 000 passes.
  2. Backprop: 1 forward + 1 backward pass (similar cost) ≈ 2–3 passes.
  3. Speed-up ≈ \(2\,000\,000/3\approx670\,000\times\) — the difference between impossible and routine.

6.5.1 · Computational graphs

Computational graphs: computation as a picture

Draw every variable as a node and every “is used to compute” as an edge. The forward pass fills in values; the backward pass fills in gradients — node by node.

In plain words

  • Node = a variable: scalar, vector, matrix, tensor, or another type.
  • Operation = a simple function of one or more variables. Complicated functions = compositions of many operations.
  • Without loss of generality, an operation returns one output variable (which can have many entries, e.g. a vector).
  • If y is computed by applying an operation to x, draw a directed edge from x to y, optionally labelled with the operation.
  • Textbook examples: (a) z = xy; (b) logistic prediction ŷ = σ(xᵀw + b); (c) ReLU layer H = max{0, XW + b}; (d) linear regression plus a weight-decay penalty.

Terms on this slide

Directed acyclic graph (DAG)
Edges have a direction and there are no cycles, so nodes can be computed in order.
Parent / child
x is a parent of y if y is computed directly from x.
Leaf
A node with no parents: an input or a parameter.
Local derivative
Derivative of one operation’s output w.r.t. one of its inputs (the edge’s “price”).

Calculation, step by step

  1. Graph (a): x = 2, y = −3 → forward z = x·y = −6.
  2. Backward: ∂z/∂z = 1. Local derivatives of multiplication: ∂z/∂x = y = −3, ∂z/∂y = x = 2.
  3. So ∂z/∂x = 1·(−3) = −3 and ∂z/∂y = 1·2 = 2: increasing x by 0.01 changes z by −0.03.

6.5.2 · Chain rule of calculus

The chain rule: from scalars to tensors

Derivatives of composed functions multiply. For vectors that becomes a Jacobian-transpose × gradient product; backprop performs one such product per operation, in a smart order.

\[ y=g(x),\ z=f(y):\qquad\frac{dz}{dx}=\frac{dz}{dy}\frac{dy}{dx} \](6.44) \[ \frac{\partial z}{\partial x_i}=\sum_j\frac{\partial z}{\partial y_j}\frac{\partial y_j}{\partial x_i}\qquad\Longleftrightarrow\qquad\nabla_{\mathbf x}z=\Big(\frac{\partial\mathbf y}{\partial\mathbf x}\Big)^{\!\top}\nabla_{\mathbf y}z \](6.45–6.46) \[ \nabla_{\mathbf X}z=\sum_j\big(\nabla_{\mathbf X}Y_j\big)\frac{\partial z}{\partial Y_j} \](6.47) tensors (j = a tuple of indices)

In plain words

  • If x → y → z, a small change in x changes y by (dy/dx) times, which changes z by (dz/dy) times that.
  • With \(\mathbf x\in\mathbb R^m\), \(\mathbf y\in\mathbb R^n\): \(\frac{\partial\mathbf y}{\partial\mathbf x}\) is the n×m Jacobian of g. Each \(x_i\) affects z through every \(y_j\), so we sum.
  • Tensors: conceptually identical — imagine flattening them into vectors, running backprop, and reshaping the gradient back.

Terms on this slide

Jacobian \(\partial\mathbf y/\partial\mathbf x\)
Matrix with entry (j, i) = \(\partial y_j/\partial x_i\).
Jacobian-vector product
Multiplying (the transpose of) a Jacobian by a gradient vector — never forming huge matrices if avoidable.
Tensor
An array with any number of indices (vector = 1, matrix = 2, image batch = 4).

Calculation, step by step

  1. x = 0.5: \(y=x^2+1=1.25\), dy/dx = 2x = 1.
  2. \(z=\sin(1.25)=0.949\), dz/dy = cos(1.25) = 0.315.
  3. dz/dx = 0.315 × 1 = 0.315.
  4. Vector: \(\mathbf y=\mathbf A\mathbf x\) with A = [[1, 2], [−1, 0.5]], x = (1, 0) → y = (1, −1); \(z=\|\mathbf y\|^2\), \(\nabla_{\mathbf y}z=2\mathbf y=(2,-2)\); \(\nabla_{\mathbf x}z=\mathbf A^\top(2,-2)=(1\cdot2+(-1)(-2),\ 2\cdot2+0.5(-2))=(4,3)\).

Connections

  • Builds onJacobian matrices (L3).
  • Leads toVanishing & exploding gradients (L7): a product of many Jacobians can shrink to 0 or blow up.
6.5.3 · Recursively applying the chain rule

Repeated subexpressions: store or recompute?

The gradient formula reuses the same subexpressions many times. Backprop computes each intermediate value once and stores it (fast, uses memory). Recomputing saves memory but can cost exponentially more time.

\[ x=f(w),\ y=f(x),\ z=f(y):\quad\frac{\partial z}{\partial w}=\frac{\partial z}{\partial y}\frac{\partial y}{\partial x}\frac{\partial x}{\partial w}=f'(y)f'(x)f'(w)=f'\big(f(f(w))\big)\,f'\big(f(w)\big)\,f'(w) \](6.49–6.52) \[ u^{(i)}=f^{(i)}\big(\mathbb A^{(i)}\big),\qquad\frac{\partial u^{(n)}}{\partial u^{(j)}}=\sum_{i:\,j\in Pa(u^{(i)})}\frac{\partial u^{(n)}}{\partial u^{(i)}}\frac{\partial u^{(i)}}{\partial u^{(j)}} \](6.48), (6.53)

In plain words

  • Eq. 6.51: compute f(w) once, store it as x (the backprop approach). Eq. 6.52: recompute f(w) whenever it’s needed (saves memory).
  • Algorithm 6.1 (forward): order the nodes so each can be computed after its parents; set the inputs \(u^{(1)}\dots u^{(n_i)}\); then compute \(u^{(i)}=f^{(i)}(\mathbb A^{(i)})\), where \(\mathbb A^{(i)}\) are the values of the parents of \(u^{(i)}\).
  • Algorithm 6.2 (backward): a second graph 𝓑 runs in exactly reverse order; each node computes \(\partial u^{(n)}/\partial u^{(j)}\) by summing over its children (6.53), one dot product per node.
  • 𝓑 has one edge per edge of the forward graph; each costs one partial derivative, one multiply and one add → cost linear in the number of edges.

Terms on this slide

\(u^{(n)}\)
The final scalar (the cost for one example or a minibatch).
\(u^{(1)}\dots u^{(n_i)}\)
The input nodes — in learning, the parameters.
\(Pa(u^{(i)})\)
The parents of node i.
Subexpression
A piece of a formula that appears several times, like f(w).

Calculation, step by step

  1. f(t) = t², w = 1.1: x = 1.21, y = 1.4641, z = 2.1436 (stored).
  2. \(f'(y)f'(x)f'(w)=2(1.4641)\cdot2(1.21)\cdot2(1.1)=2.928\times2.42\times2.2=15.59\).
  3. Check: z = w⁸, so dz/dw = 8w⁷ = 8 × 1.9487 = 15.59 ✓.
  4. Recompute version for n = 3: f(w) is evaluated 3 times instead of once; for long chains the waste grows like n²/2.
6.5.4 · Back-propagation in a fully connected MLP

Algorithms 6.3 & 6.4: forward and backward for an MLP

Backward pass, layer by layer: start with \(\mathbf g=\nabla_{\hat{\mathbf y}}J\); at each layer multiply by f′ (element-wise), read off the weight gradient \(\mathbf g\mathbf h^{(k-1)\top}\), then pass \(\mathbf W^{(k)\top}\mathbf g\) down.

\[ \textbf{forward: }\ \mathbf h^{(0)}=\mathbf x;\ \ \mathbf a^{(k)}=\mathbf b^{(k)}+\mathbf W^{(k)}\mathbf h^{(k-1)};\ \ \mathbf h^{(k)}=f(\mathbf a^{(k)});\ \ \hat{\mathbf y}=\mathbf h^{(l)};\ \ J=L(\hat{\mathbf y},\mathbf y)+\lambda\Omega(\boldsymbol\theta) \]Algorithm 6.3 \[ \textbf{backward: }\ \mathbf g\leftarrow\nabla_{\hat{\mathbf y}}J;\ \ \text{for }k=l,\dots,1:\ \ \mathbf g\leftarrow\mathbf g\odot f'(\mathbf a^{(k)});\ \ \nabla_{\mathbf b^{(k)}}J=\mathbf g+\lambda\nabla_{\mathbf b^{(k)}}\Omega;\ \ \nabla_{\mathbf W^{(k)}}J=\mathbf g\,\mathbf h^{(k-1)\top}+\lambda\nabla_{\mathbf W^{(k)}}\Omega;\ \ \mathbf g\leftarrow\mathbf W^{(k)\top}\mathbf g \]Algorithm 6.4

In plain words

  • Algorithm 6.3 maps the parameters to the loss \(L(\hat{\mathbf y},\mathbf y)\) for one (input, target) example, plus a regularizer Ω.
  • Algorithm 6.4 walks back: \(\mathbf g\) is always “the gradient w.r.t. the current layer’s output”. ⊙ = element-wise product (the activation’s slope gates the gradient).
  • These algorithms are simple but specialized. Modern software uses general backprop that works on any computational graph (symbolic computation data structures).

Terms on this slide

\(\mathbf a^{(k)}\)
Pre-activation of layer k (before f).
\(\mathbf h^{(k)}\)
Activation (output) of layer k.
⊙
Element-wise product.
Ω(θ)
Regularizer, e.g. sum of squared weights.

Calculation, step by step (1-1-1 net)

  1. x = 1, w₁ = 2, w₂ = 3, ReLU hidden, linear output, L = ½(ŷ − y)², y = 5, no biases.
  2. Forward: a₁ = 2, h = 2, ŷ = 3·2 = 6, L = 0.5.
  3. g = ŷ − y = 1. Output layer: ∇w₂ = g·h = 2. Pass down: g = w₂·g = 3.
  4. Hidden: ReLU′(2) = 1 → g = 3; ∇w₁ = g·x = 3.

6.5.6 · General back-propagation

General backprop: sum over paths, done by table filling

Start with ∂z/∂z = 1, multiply by Jacobians going backward, and sum where paths meet. Expanding the chain rule naively is a sum over exponentially many paths; backprop’s dynamic programming keeps it linear.

\[ \frac{\partial u^{(n)}}{\partial u^{(j)}}=\sum_{\substack{\text{paths }(u^{(\pi_1)},\dots,u^{(\pi_t)})\\ \pi_1=j,\ \pi_t=n}}\ \prod_{k=2}^{t}\frac{\partial u^{(\pi_k)}}{\partial u^{(\pi_{k-1})}} \](6.55)

In plain words

  • Gradient of z with respect to itself = 1. For each parent, multiply the current gradient by the Jacobian of the operation that produced the child. Keep going until you reach x; sum gradients that arrive by different paths.
  • Cost (counting graph operations, each roughly equal): forward ≤ n nodes; backward adds one Jacobian-vector product per edge; a DAG has at most O(n²) edges → never more than O(n²). Most networks are roughly chains → O(n).
  • One graph “operation” can be huge (a matrix multiply with millions of entries), so runtime per op varies.
  • Naive expansion (6.55) = one term per path; the number of paths can grow exponentially with depth, redoing the same \(\partial u^{(i)}/\partial u^{(j)}\) many times.
  • Backprop = table filling: one slot per node storing ∂z/∂node, filled in order → dynamic programming.

Terms on this slide

Path
A chain of edges from node j to the output n.
Dynamic programming
Solve a big problem by storing answers to overlapping sub-problems and reusing them.
O(n) / O(n²)
Cost grows linearly / quadratically with the number of nodes n.

Calculation, step by step

  1. Diamond graph: a = 2w, b = 3w, z = a·b. Two paths from w to z.
  2. Path via a: (∂z/∂a)(∂a/∂w) = b · 2. Path via b: (∂z/∂b)(∂b/∂w) = a · 3.
  3. At w = 1 (a = 2, b = 3): 3·2 + 2·3 = 12. Check: z = 6w² → dz/dw = 12w = 12 ✓.
  4. A graph of depth 30 with 2 nodes per layer has \(2^{30}\approx10^9\) paths, but only ~120 edges — backprop does ~120 multiplies.
6.5.7 · Example: back-propagation for MLP training

Full example: one hidden layer, cross-entropy + weight decay

Two paths lead from J to the weights: through the cross-entropy (back through softmax, matmul, ReLU) and through the weight decay (always \(2\lambda\mathbf W\)). Backward costs about the same as forward; memory is dominated by stored activations.

\[ \mathbf H=\max\{0,\mathbf X\mathbf W^{(1)}\},\qquad\mathbf U^{(2)}=\mathbf H\mathbf W^{(2)},\qquad J_{\text{MLE}}=\text{cross\_entropy}\big(\mathbf y,\mathbf U^{(2)}\big) \] \[ J=J_{\text{MLE}}+\lambda\Big(\sum_{i,j}\big(W^{(1)}_{i,j}\big)^2+\sum_{i,j}\big(W^{(2)}_{i,j}\big)^2\Big) \](6.56) \[ \nabla_{\mathbf W^{(2)}}J=\mathbf H^{\top}\mathbf G+2\lambda\mathbf W^{(2)},\qquad\mathbf G'=\big(\mathbf G\mathbf W^{(2)\top}\big)\odot\mathbf 1\big[\mathbf X\mathbf W^{(1)}>0\big],\qquad\nabla_{\mathbf W^{(1)}}J=\mathbf X^{\top}\mathbf G'+2\lambda\mathbf W^{(1)} \]

In plain words

  • Minibatch SGD: X is a minibatch design matrix, y its labels. No biases (to keep it simple); the graph language has relu, matmul and cross_entropy operations.
  • U⁽²⁾ are unnormalized log-probabilities; cross-entropy with the targets = maximum likelihood.
  • Weight-decay path: adds \(2\lambda\mathbf W^{(i)}\) to each weight gradient.
  • Cross-entropy path: G = gradient on U⁽²⁾. Short branch: \(\mathbf H^\top\mathbf G\) to W⁽²⁾ (matmul rule, 2nd argument). Long branch: \(\nabla_{\mathbf H}J=\mathbf G\mathbf W^{(2)\top}\) (matmul rule, 1st argument); ReLU zeroes entries where \(\mathbf X\mathbf W^{(1)}<0\) → G′; then \(\mathbf X^\top\mathbf G'\) to W⁽¹⁾.
  • Cost: forward multiplies by each W, O(w) multiply-adds (w = number of weights); backward multiplies by each Wᵀ — same cost.
  • Memory: store the ReLU input until the backward pass returns: O(m·n_h).

Terms on this slide

G
Gradient of the loss w.r.t. the logits U⁽²⁾ (= (P − Y)/m for softmax cross-entropy).
\(\mathbf 1[\cdot]\)
Indicator: 1 where the condition holds, 0 elsewhere.
m, n_h
Minibatch size and number of hidden units.

Calculation, step by step (shapes & cost)

  1. m = 128, inputs 784, n_h = 100, 10 classes: X 128×784, W⁽¹⁾ 784×100, H 128×100, W⁽²⁾ 100×10, G 128×10.
  2. Weights w = 784·100 + 100·10 = 79 400 → forward ≈ 128 × 79 400 ≈ 10.2 million multiply-adds.
  3. Backward: \(\mathbf H^\top\mathbf G\) (100×10), \(\mathbf G\mathbf W^{(2)\top}\) (128×100), \(\mathbf X^\top\mathbf G'\) (784×100) — the same order of work.
  4. Stored for the backward pass: \(\mathbf X\mathbf W^{(1)}\), 128 × 100 = 12 800 numbers.

6.5.8 · Complications

What real implementations must also handle

Real autodiff libraries go beyond the clean algorithm: multi-output operations, memory-efficient summation, many data types, undefined gradients, and higher-order derivatives.

Multiple outputsMax value and its index are best computed in one pass through memory → one operation with two outputs.
Summation buffersBackprop often adds many tensors. Computing each separately and then summing has a memory bottleneck; instead keep one buffer and add each value as it is computed.
Data types32-bit and 64-bit floats, integers… each needs a careful policy (e.g. no gradient through an integer index).
Undefined gradientsSome operations have undefined gradients (e.g. ReLU exactly at 0, sqrt at 0); the library must track whether the requested gradient is defined.
Higher-order derivativesHessians and other second derivatives need special, efficient methods (e.g. Hessian-vector products) — see the textbook.

Terms on this slide

Autodiff
Automatic differentiation: software that builds and runs the backward graph for you (PyTorch, TensorFlow, JAX).
Buffer
A block of memory that accumulates partial results.
Hessian-vector product
Computing Hv without forming the huge Hessian H.

Calculation, step by step

  1. Summing 100 gradient tensors of 1 million floats each: storing all first needs 100 × 4 MB = 400 MB.
  2. With one accumulation buffer: 4 MB (+ one tensor at a time).
  3. sqrt at 0: \(\frac{d}{dx}\sqrt x=\frac{1}{2\sqrt x}\to\infty\) — undefined; that is why batch norm adds δ inside \(\sqrt{\delta+\sigma^2}\).

Wrap-up

Summary: how it all connects

Write the computation as a graph; run it forward and store the values; then apply the chain rule backward, once per edge, summing over paths. The gradient costs about one extra forward pass.

Remember

Backprop computes gradients; the optimizer learns. Forward cost ≈ backward cost.
